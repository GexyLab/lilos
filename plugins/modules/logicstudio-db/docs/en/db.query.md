# SQL · Query (query)

`db.query` · Database · [Database blocks (SQL)](logicstudio-db) · version 1

Runs a SQL statement on a connection and sends the result: the rows, the first row, the first value, how many rows it changed. Inside the SQL write `:name` for a **parameter**: the value comes from an added input called `name` and goes to the database separately, never inside the SQL text, so no other SQL can be "injected".

## Inputs

| Port | Type | Description |
|---|---|---|
| **run** (`run`) | pulse | Any value arriving here starts the query. |
| **connection** (`connection`) | object | The reference from the **connection** output of a connection block (or the **transaction** output of a [SQL · Transaction (BEGIN · COMMIT · ROLLBACK)](db.transaction)). It does not start the block. |
| **SQL** (`sql`) | text | Hidden. If it has a non-empty value, it takes the place of the **SQL** of the settings. It does not start the block. |

## Outputs

| Port | Type | Description |
|---|---|---|
| **rows** (`rows`) | list | The rows of the result, each an object `{ "column": value }`. Empty if the statement gives no rows. |
| **first row** (`first`) | object | The first row, or `null` if there are none. |
| **value** (`value`) | any | Hidden. The first value of the first row (for example the result of `SELECT COUNT(*)`), or `null`. |
| **rows changed** (`affected`) | number | How many rows an `UPDATE`, `DELETE` or `INSERT` changed. For a `SELECT` the number depends on the database: do not use it. |
| **last id** (`lastId`) | any | Hidden. The last number generated by an insert (`AUTO_INCREMENT`, `IDENTITY`...), where the database gives it; otherwise `null`. |
| **columns** (`fields`) | list | Hidden. The names of the result's columns, in order. |
| **cut** (`truncated`) | yes/no | Hidden. `true` if there were more rows than the maximum and the others did not come out. |
| **Exception** (`error`) | object | When the query fails: missing or closed connection, a parameter without a value, a SQL error, time out, result too big... |

The hidden ports are shown with the **eye** in the **Properties**.

## Settings

| Setting | Values | Default | What it does |
|---|---|---|---|
| **SQL** (`sql`) | multi-line text | `SELECT * FROM tabella WHERE id = :id` | The statement to run, when the **SQL** input has no value. At most 100000 characters. |
| **Rows, at most (0 = the module's limit)** (`maxRows`) | 0 to 1000000 | 0 | How many rows to send at most. 0: the limit of the module settings (10000 by default). It cannot go over that limit. |

## Added ports

In the **Properties**, **Ports** section, with **Add input** you can add up to 32 inputs of any type (fewer, if the engine's general limit on added ports is lower: see [Limits](logicstudio-engine/limits)). Each added input is a **parameter** of the query: it is called **parameter 1**, **parameter 2**... and must be **renamed** with the name used in the SQL, without the colon: for `:id` the input is called `id`.

The added inputs **only hold their value**: a value arriving there does not start the query, even if the input "starts it". The query starts only with **run**. See [How a block works](ide/blocks).

## How it works

When a value arrives on **run**:

1. The block takes the SQL (the one of the **SQL** input, if it has a non-empty value, otherwise the one in the settings).
2. It collects the values of the added inputs: `{ name: value }`.
3. It asks the kernel to run the statement on the connection, with the row limit.
4. When the result arrives, it sends the outputs.

### The parameters

- `:name` (letters, digits and `_`, starting with a letter or `_`) becomes the database's placeholder (`$1` for PostgreSQL, `?` for MySQL and SQLite, `@p1` for SQL Server, `:1` for Oracle, `{p1:Type}` for ClickHouse). The value travels separately.
- These are not parameters: a `:` inside a string (`'12:30'`), a quoted name, a comment (`-- …`, `/* … */`), PostgreSQL's cast (`value::int`) and PostgreSQL's text between `$$…$$`. Neither is a `:` followed by a digit or preceded by a letter (as in `12:30` or `a:b`).
- A `:name` without an input that has a value gives the error "Manca il valore del parametro :nome (aggiungi un ingresso «nome» al blocco)" (the value of parameter :name is missing: add an input "name" to the block): so a misspelled name does not become a silent `NULL`. An input that receives `null` sends `NULL` instead.
- A parameter is **a value**: you cannot use it for a table or column name. For those use [SQL · Read table (SELECT)](db.select) and the other blocks without SQL, which check the names.
- Objects and lists as values become JSON text (PostgreSQL receives them as JSON). An object `{ "$bytes": "…" }` becomes binary again.
- At most 2000 parameters for SQL Server, 1000 for Oracle and ClickHouse, 999 for SQLite, 30000 for PostgreSQL, MySQL and MariaDB.

### The result

- The rows are objects with the column names (upper case for Oracle). Dates as ISO text, big numbers as numbers or text, binaries as `{ "$bytes": "base64" }`: see [Database blocks (SQL)](logicstudio-db).
- The result is limited in rows (the **Rows, at most**, and in any case those of the module) and in size (4096 KB by default, measured as JSON). With more rows, **cut** is true and the others do not come out; with a result that is too big, an error.
- A statement that gives no rows (`INSERT`, `UPDATE`, `CREATE TABLE`...) sends **rows** empty, **first row** `null` and **rows changed**.

### More statements

PostgreSQL (without parameters), SQL Server and SQLite (without parameters) accept more statements in a query, and send the last result. MySQL, MariaDB, Oracle and ClickHouse accept only one per query.

### Inside a transaction

Link the **transaction** output of a [SQL · Transaction (BEGIN · COMMIT · ROLLBACK)](db.transaction) block to **connection** in place of the connection's one: the query runs inside the transaction and is committed or cancelled with it.

### The time

The time limit of an operation is 30 seconds (module setting). If it is longer than the time limit of a block, the block stops first ("SQL · Query (query) took more than 30 s"). Keep a long query for a [SQL · Read rows one by one (cursor)](db.cursor) block or filter it with `LIMIT`.

## Examples

### 1. Searching with a parameter

**SQL**: `SELECT id, cliente, totale FROM ordini WHERE cliente = :cliente ORDER BY id DESC`. Add an input and call it `cliente`.

```
[SQL · PostgreSQL (connect)] connection ──▶ connection [SQL · Query (query)] rows ──▶ rows [Table]
[Text field: cliente] text ──▶ cliente
[Button: Search] pressed ──▶ run                    Exception ──▶ value [Print (console.log)]
```

If you write `Rossi' OR '1'='1` in the field, the query looks for a customer with exactly that name: the SQL does not change.

### 2. Counting and showing a number

**SQL**: `SELECT COUNT(*) AS n FROM ordini WHERE totale > :minimo`. Add an input `minimo`.

```
[SQL · MySQL · MariaDB (connect)] connection ──▶ connection [SQL · Query (query)] value ──▶ value [Value: ordini grandi]
[Number field: minimo] value ──▶ minimo
[Interval (setInterval): 30 s] pulse ──▶ run
```

The hidden **value** output is the first value of the first row: the number `n`. Every 30 seconds the [Value](ui.value) updates.

### 3. Writing and knowing how many rows

**SQL**: `UPDATE ordini SET stato = :stato WHERE id = :id`. Add the inputs `stato` and `id`.

```
[SQL · SQLite (open)] connection ──▶ connection [SQL · Query (query)] rows changed ──▶ a [Compare (== != < >): a < b] if true ──▶ send [Notify: "Ordine non trovato"]
[Selection: stato] value ──▶ stato                              [Constant · Variable: 1] value ──▶ b
[Number field: id] value ──▶ id
[Button: Change] pressed ──▶ run
```

If no row has that `id`, **rows changed** is 0 and [Compare (== != < >)](core.compare) with `a < b` and 1 says "true": [Notify](lilos.notify) warns you.

## Errors

The messages are in Italian, as the block sends them. In English:

| Message | When |
|---|---|
| Manca la query SQL | The SQL is empty (the SQL query is missing). |
| Query troppo lunga (al massimo 100.000 caratteri) | The SQL is over 100000 characters (query too long). |
| Manca il valore del parametro :nome (aggiungi un ingresso «nome» al blocco) | The SQL has `:name` but there is no added input `name` with a value. |
| Troppi parametri (al massimo 2000) | The query has more parameters than the database accepts (too many parameters). |
| Manca la connessione: collega l'uscita «connessione» del blocco di connessione all'ingresso «connessione» | The **connection** input has no value (link the connection block's output). |
| Connessione chiusa (o di un altro programma): riaprila con il blocco di connessione | The connection was closed (or belongs to another program). |
| Questa non è una connessione né una transazione | The **connection** input holds the reference of a cursor or a listening. |
| Risultato troppo grande (… KB, al massimo … KB): chiedi meno righe o colonne | The result is over the maximum size. |
| Troppe operazioni sul database: al massimo 600 al minuto | You went over the operations per minute. |
| Il database non ha risposto in 30 s | The query went over the time limit. |
| Il database è aperto in sola lettura | (SQLite) A statement that writes on a database opened with **Read only**. |
| … (a message from the database) | The SQL is not valid, the table does not exist, a database rule is not respected... The message is the database's, on one line. |
