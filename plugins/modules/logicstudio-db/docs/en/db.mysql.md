# SQL · MySQL · MariaDB (connect)

`db.mysql` · Database · [Database blocks (SQL)](logicstudio-db) · version 1

Opens a connection to a **MySQL** or **MariaDB** server and sends the reference, to be linked to the **connection** input of the other database blocks. The hidden **server** output says which of the two it is (for example `MariaDB 11.4.2`).

## Inputs

| Port | Type | Description |
|---|---|---|
| **connect** (`connect`) | pulse | Any value arriving here opens the connection (if this block already has one, it closes it first). |
| **close** (`close`) | pulse | Hidden. Closes the connection. |
| **password** (`password`) | text | Hidden. The password, if you do not want to keep it in the settings. If it has a non-empty value, it takes the place of the **Password** of the settings. **It does not start the block**: it only holds the value for the next connection. |

## Outputs

| Port | Type | Description |
|---|---|---|
| **connection** (`connection`) | object | The reference to the open connection. It only works for this program. |
| **connected** (`connected`) | yes/no | `true` when the connection is open, `false` when it is closed with **close**. |
| **server** (`info`) | object | Hidden. What the server is: `{ "kind": "mysql", "label": "MySQL / MariaDB", "name": "db.esempio.it:3306/negozio", "server": "MariaDB 11.4.2" }`. |
| **Exception** (`error`) | object | When the connection fails: no such server, wrong password, address not allowed, time out... |

The hidden ports are shown with the **eye** in the **Properties**.

## Added ports

This block has no added ports.

## Settings

| Setting | Values | Default | What it does |
|---|---|---|---|
| **Server (name or address)** (`host`) | text | empty | The database computer: a name or an address. |
| **Port** (`port`) | 1 to 65535 | 3306 | The port of MySQL and MariaDB. |
| **Database** (`database`) | text | empty | The database to connect to. Empty: none (then table names go with the database, `negozio.clienti`). |
| **User** (`user`) | text | empty | The user. |
| **Password** (`password`) | password field | empty | The user's password. What you type is not shown and is sealed by the engine. |
| **Encrypted connection (TLS)** (`tls`) | No (not encrypted), Encrypted (certificate not checked), Encrypted and checked | No (not encrypted) | Whether and how to encrypt the connection. |
| **Connections in the pool** (`poolSize`) | 1 to 10 | 4 | How many connections to the server the block keeps open at most (a transaction takes one). |
| **Connect at start** (`atStart`) | yes / no | yes | If ticked, the block connects as soon as the program starts. If not, only with **connect**. |

## How it works

- **When the program starts**, if **Connect at start** is ticked, the block opens the connection and sends **connection**, then **connected**, then **server**. Otherwise the connection opens only with **connect**.
- With **connect** the block closes the connection it already had (its old reference stops working) and opens a new one.
- With **close** the block closes the connection and sends `connected = false`.
- When the program stops, all the connections (and the transactions and cursors inside them) close.
- The connection is made by the **kernel**. The server's name is resolved and every address checked; this computer and the local network stay blocked unless an administrator allows them; the lilOS database never opens. See [Database blocks (SQL)](logicstudio-db).
- The **Password** is sealed by the engine for you, on this lilOS: on another lilOS or for another user it gives "Password non leggibile: va inserita di nuovo nelle Proprietà del blocco (…)" (password not readable, type it again) and must be typed again. It can also come from the hidden input **password**, for example from [Input (readline)](core.consoleRead) with **Hide what is typed**.

### MySQL and MariaDB in particular

- **One statement at a time**: each query may have a single statement (no statements one after the other). A procedure that gives several results sends the last one that has rows.
- **Values**: big integers come out as numbers when they are exact, as text otherwise; `DECIMAL` comes out as **text** (so it loses no digits). Dates and times come out as ISO text in UTC. An ISO text with its zone (`2026-11-11T10:05:00Z`) sent to a parameter becomes a date, because MySQL does not accept the "T…Z" form. `TINYINT(1)` comes out as 0 and 1. Objects and lists sent as parameters become JSON text.
- **Parameters**: `:name` becomes `?`; strings, backtick-quoted names and comments are not touched.
- **Writing**: there is no `RETURNING`: [SQL · Insert (INSERT)](db.insert) sends in **last id** the value generated by the `AUTO_INCREMENT` column; the hidden **rows inserted** output is empty.
- **Names**: the table and column names of the blocks without SQL are quoted with backticks, as MySQL wants.
- **Cursor**: [SQL · Read rows one by one (cursor)](db.cursor) reads the rows from the server as they go; if you stop it before the end, that cursor's connection closes.
- **Tables**: [SQL · Tables and columns (schema)](db.tables) lists the tables and views of the chosen database.
- **Isolation**: *Snapshot* does not exist and is ignored.
- Notifications (LISTEN and NOTIFY) are not available.

## Examples

### 1. Looking for a customer

```
[Text field: nome] text ──▶ nome [SQL · Query (query): SELECT * FROM clienti WHERE nome LIKE :nome] rows ──▶ rows [Table]
[SQL · MySQL · MariaDB (connect)] connection ──▶ connection
[Button: Search] pressed ──▶ run
```

In the **SQL · Query** block add an input and call it `nome`. With the value `Ros%` the query looks for customers starting with "Ros". The value goes as a parameter, never inside the SQL text.

### 2. Adding a row and knowing its number

```
[SQL · MySQL · MariaDB (connect)] connection ──▶ connection [SQL · Insert (INSERT): clienti] last id ──▶ value [Print (console.log)]
[Text field: nome] text ──▶ nome (added input)
[Button: Add]      pressed ──▶ run
```

In the **SQL · Insert (INSERT)** block add an input and call it `nome`: it is the row's column. After the insert, **last id** sends the number MySQL gave to the new row.

## Errors

The messages are in Italian, as the block sends them; the server's own messages are in English. The common errors (server, address, quotas, password not readable...) are listed on the [Database blocks (SQL)](logicstudio-db) page. In addition:

| Message | When |
|---|---|
| Manca il server | **Server** is empty (missing server). |
| L'amministratore non permette i database MySQL / MariaDB (impostazioni del modulo logicstudio-db) | MySQL and MariaDB are switched off in the module settings (the administrator does not allow them). |
| MySQL / MariaDB non ha risposto in 30 s | The server did not answer within the time limit of an operation. |
| Access denied for user '…' | Wrong user or password (the server's message). |
| Unknown database '…' | The database does not exist (the server's message). |
| You have an error in your SQL syntax… | The SQL is not valid, or has more than one statement (the server's message). |
